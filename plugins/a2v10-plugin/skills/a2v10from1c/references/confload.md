# confload — інструмент завантаження даних

Переносить дані з бази 1С стандартним інтерфейсом OData у **розгорнуту** базу застосунку A2v10.
Рядки й більше нічого: схеми не створює, метаданих не править, у джерело не пише.

До цього скіла інструмент не прив'язаний — потрібні рівно дві речі: застосунок A2v10 у режимі
metaendpoint із розгорнутою базою і заповнений `origin` у його `metadata.json`. **Джерело ж
незамінне:** 1С зашита в код — baseline стандартних реквізитів, імена наборів `Catalog_`/`Document_`,
суфікси `_Key` і `_Type`, і те, як 1С пише «не заповнено» (мінімальна дата, порожній GUID).

## Встановлення

Маніфестом у корені застосунку — звідти інструмент і запускається:

```
dotnet new tool-manifest
dotnet tool install A2v10.Confload
dotnet confload --version
```

Не `--global`: голе ім'я береться з `PATH`, і яким саме інструментом заливали дані — ніде не
записано.

## Конфігурація — із самого застосунку

Інструмент запускається **з кореня застосунку** і знаходить його сам: поруч лежить тека `*WebApp*`
з `appsettings.json`, а `UserSecretsId` береться з її `.csproj`. Змінні середовища накладаються
останніми.

```jsonc
"ConnectionStrings": { "Default": "Server=…;Database=…" },
"OData": {
  "Url": "http://host/base/odata/standard.odata/",   // скіс у кінці обов'язковий
  "UserName": "odata",
  "PageSize": 0        // 0 — набір одним запитом; >0 — посторінково ($top/$skip)
}
```

**Пароль в `appsettings.json` не пишеться й аргументом не передається:** `OData:Password` в user
secrets або `OData__Password` у середовищі.

## Команди

Кожна команда друкує один об'єкт JSON: `{"success": true, "data": …}` або
`{"success": false, "error": {"message": …}}`. Інтерактиву немає.

| команда | що потрібно | що робить |
|---|---|---|
| `data plan [endpoint]` | лише метадані | відповідність: колонка цілі ← властивість джерела, плюс `unmapped` |
| `data table <endpoint>` | база | тип-таблиця з типами SQL і чим заповнюється кожна колонка |
| `data count [endpoint]` | джерело | скільки записів у джерелі |
| `data peek <endpoint> [--top N]` | і те, і те | кілька записів, перетворених під ціль; нічого не пише |
| `data load --endpoint <p>… \| --all` | і те, і те | завантажує й зливає |
| `fk disable` / `fk enable` | база | зовнішні ключі на час перенесення і назад |

Ендпоінт називається текою — `catalog/company`. Без імені `plan` і `count` беруть усі завантажувані.

Першими дивитися `data plan` і `data peek`: перша показує, у що інструмент вірить, друга — ту саму
віру на живих записах.

## Що має оголосити ціль

```jsonc
// catalog/company/metadata.json
{
  "table": "Companies",
  "origin": "Организации",                 // ім'я об'єкта в джерелі, без виду
  "fields": {
    "Code":                  { "type": "string", "length": 9, "origin": "Code" },
    "HeadCompany":           { "type": "ref", "target": "/catalog/company", "origin": "ГоловнаяОрганизация" },
    "LegalIndividualPerson": { "type": "enum", "target": "/enum/legalform", "origin": "ЮридическоеФизическоеЛицо" }
  }
}

// enum/legalform/metadata.json
{ "table": "LegalForms", "values": [ { "id": "Legal", "origin": "ЮридическоеЛицо" } ] }
```

- `origin` — ім'я **як його пише джерело**, без суфіксів OData: `ГоловнаяОрганизация`, а не
  `ГоловнаяОрганизация_Key`. Написання обирає читач, за самим записом;
- стандартний реквізит пишеться англійським іменем 1С: `Code`, `Owner`, `Number`, `Date`;
- **baseline платформи `origin` не несе** — інструмент його знає (таблиця нижче);
- колонка без `origin` і поза baseline **не завантажується**. Це законно, і `data plan` називає її
  в `unmapped`, щоб порожньою вона не лишилася мовчки;
- **перелік** відображається через свій ендпоінт: джерело шле ім'я значення 1С, ціль зберігає свій
  ключ, тому `origin` потрібен кожному значенню, яке може приїхати.

### Baseline за видом

| вид ендпоінта | колонка цілі ← стандартний реквізит джерела |
|---|---|
| `catalog`, `accplan` | `Id ← Ref`, `Name ← Description`, `Void ← DeletionMark`, `IsSystem ← Predefined` |
| `document` | `Id ← Ref`, `Date ← Date`, `Done ← Posted`, `Void ← DeletionMark` |
| рядок колекції (`details`) | `RowNumber ← LineNumber` |

**Переліки як об'єкти не завантажуються:** їхні рядки пише деплой із `metadata.json`, а завантаженню
вони дають лише карту значень. `--all` їх пропускає.

## Як іде завантаження

1. **План** — з самого `metadata.json`. Набір OData це вид ендпоінта плюс `origin` таблиці
   (`catalog` + `Организации` → `Catalog_Организации`); схема SQL і ім'я типу-таблиці — за угодами
   платформи (`cat.[Companies]`, `cat.[Company.Meta.TableType]`).
2. **Форма цілі** — `declare @x <тип-таблиця>; select * from @x;`. Схема цієї порожньої вибірки і є
   склад типу: колонки, типи, довжини і — що важливо — порядок.
3. **Читання** — записи набору, потоком. **`$select` не будується:** ім'я посилання наперед
   невідоме (`X_Key` у звичайного, `X` плюс `X_Type` у поліморфного), а неіснуюча властивість у
   `$select` валить увесь запит чотирьохсотим. Зайві поля по мережі дешевші за здогадки.
4. **Перетворення** — `DataTable` за формою типу-таблиці, усі колонки й у тому ж порядку;
   незаповнені лишаються `DBNull`.
5. **Merge** — табличний параметр і `merge … on t.[Id] = s.[Id]`, update плюс insert. Беруть участь
   лише заповнені колонки, тож `rv`, штампи й решта платформного не чіпаються. Партія — 10 000 рядків.

Завантаження **ідемпотентне**: ключ — `Id` запису джерела, тому повтор безпечний, а порядок об'єктів
не має значення.

### Перетворення

| джерело | ціль | чому |
|---|---|---|
| властивості немає, `null`, порожній рядок | `DBNull` | «не заповнено» |
| рядок | обрізається, ріжеться по довжині колонки | 1С доповнює код фіксованої довжини: `"00000001 "` |
| `0001-01-01T00:00:00` | `DBNull` | «не заповнено» 1С віддає мінімальною датою |
| `00000000-0000-0000-0000-000000000000` | `DBNull` | порожнє посилання |
| ім'я значення переліку | ключ цілі | `ЮридическоеЛицо` → `Legal` |
| значення немає в карті переліку | **прогін падає** | мовчки покладене порожнє гірше |

## Зовнішні ключі

```
dotnet confload fk disable
dotnet confload data load --all
dotnet confload fk enable
```

Вимикаються один раз на все перенесення і вмикаються в кінці. «Правильного порядку» завантаження не
існує: довідники посилаються одне на одного циклами (організація → основний рахунок → організація).

`fk enable` рахує порушення **до** вмикання, за кожним ключем окремо, і вмикає лише чисті; ключ із
порушеннями лишається вимкненим і називається в помилці таблицею, колонкою та числом рядків.
Платформні схеми (`dbo`, `a2sys`, `a2ui`, `a2meta`, `a2wf`, `a2security`) не чіпаються.

Порушення після повного завантаження майже завжди означає одне: колонка цілі оголошена звичайним
`ref`, а посилання в джерелі поліморфне. Рядкам з іншим видом власника нема куди лягти. Лагодиться
ціль — поліморфна колонка або відбір рядків в ендпоінті, — а не дані.

## Помилки

| повідомлення | що сталося |
|---|---|
| `No application found: … has no *WebApp* folder…` | запущено не з кореня застосунку |
| `appsettings.json has no connection string Default` / `no application:modules` | конфігурація застосунку неповна |
| `appsettings.json has no OData:Url` | немає секції джерела |
| `401 (Unauthorized)` | пароль не приїхав: він у user secrets або в середовищі |
| `No endpoint <path>: there is no metadata.json` | хибний шлях ендпоінта |
| `<path>: metadata.json declares no origin…` | ендпоінт не завантажується; заповнити `origin` |
| `Endpoint kind <kind> is mapped to neither an SQL schema nor an OData set` | вид, якого інструмент ще не знає |
| `No table type <name>` | застосунок не розгорнуто або розгорнуто без цього ендпоінта |
| `<endpoint>.<column>: <value> is not among the enum values` | у переліку немає `origin` для значення, яке є в даних |
| `<endpoint>.<column>: <value> is not a GUID` | колонка посилальна, властивість джерела — ні |
| `Foreign keys are not enabled - dangling references: …` | `fk enable` знайшов висячі посилання; кожен ключ названо |
| `Foreign key <name> is composite - no report is built for it` | складені зовнішні ключі не підтримуються |

## Межі

- **Колекції (`details`) ще не завантажуються.** План їх несе, шлях завантаження не написано.
- **Нічого не видаляється.** Рядок, якого в джерелі вже немає, лишається в цілі: `when not matched
  by source` не пишеться.
- **Посторінковість не зміряна.** `PageSize` вимкнено; про `$skip` на великих таблицях 1С кажуть,
  що деградує.
- **Переліки — карта значень, а не завантажувані об'єкти.**
