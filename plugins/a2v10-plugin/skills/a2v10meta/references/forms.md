# forms — модель форм

Форми metaendpoint описуються декларативно, XAML будується з опису. Блок `forms` у `metadata.json`, поруч із `fields` / `initialValues`. Нерегулярна форма мовою **не описується** — це eject у XAML ([materialize.md](materialize.md)); лазівок на кшталт `template` / `custom` / фрагмента XAML усередині JSON немає.

## Три форми endpoint'а

Ключів у `forms` рівно три: **`index`** (сторінка списку), **`browse`** (той самий список діалогом вибору) і **`edit`** (картка запису). Четвертий ключ — помилка завантаження.

- **Не оголошена форма будується за замовчуванням.** Оголошена **замінює дефолт цілком**, ніколи повузлово: написати форму = набрати її з нуля.
- **Форма належить endpoint'у, не таблиці** — `forms` лежить поруч із `fields`. Між endpoint'ами шарується по ключу форми, значення — все-або-нічого: документ над `storage`, що оголосив свій `edit`, і далі показує `index` кореня, доки не оголосить свій. Операції форм не мають.
- **`is` у корені — тільки в `edit`**, і там обов'язковий: `"page"` або `"dialog"`. У `index` / `browse` розкрій кореня диктує дія, ключа там немає.
- **Форми має не кожен kind:** `catalog`, `document`, `journal`, `accplan`, `ledger`. У `enum`, `autonum` і службових таблиць trait'ів форм немає зовсім. `report` малює звітний рушій ([report.md](report.md)), `forms` до нього не застосовується.
- **За замовчуванням `edit`** ставить **одну** смугу табів на всі колекції запису; **`index`** ставить панель фасетів із простору фільтрів (нижче), крім входів `<Поле>Role` — їх бере лише оголошена форма; без жодного фільтра панелі немає.

**Що форма може називати.** `index` / `browse` — index-колонки; `edit` — edit-колонки, плюс те, що додає trait (сьогодні `Tags`), плюс `$`-імена `properties` своєї області — запису або виду рядка під `tab` (version >= 8668). Ім'я поза своїм списком — «поле не знайдено».

**Чи можна вводити — виводиться, не оголошується.** Поле під властивістю без `set` і колонка з `sqlAs` показуються без вводу. Властивість із `set` — звичайний контрол свого домену (version >= 8668). Підпис `$`-імені — `@[<ім'я без $>]`. Контрол виводиться з **домену поля**: `Bool` → чекбокс, `Ref` → лукап, `Memo` → textarea, `Date` → пікер. Захотілось написати контрол у формі — домен описано невірно, чинити `fields`.

**Документ з `operations`** ([metadata.md](metadata.md) → «`document` — таблиця й операції»):
- заголовок картки — `@[Operation.<документ>]`; документ з однією неявною операцією показує заголовком поле `Operation`;
- поле `Operation` — комбік операцій документа; форма за замовчуванням кладе його в `taskpad`;
- «Створити» в реєстрі — меню операцій, кожна відкриває `new?Op=<op>`.

## Роль і якір

| Ключ | Що | Словник |
|---|---|---|
| `is` | роль вузла | **замкнутий**: `group` / `tabs` / `tab` / `dataGrid` / `treeGrid` / `taskpad` / `toolbar` / `pager` / `filters` |
| `scope` (+ `kind`) | колекція, яку показує таб | імена з metadata |

- **`is` обов'язковий на кожному вузлі.** Шлях у `is` — помилка: не `{ "is": "Rows" }`, а `{ "is": "tab", "scope": "Rows" }`.
- `group` / `tabs` / `tab` — форма запису; `dataGrid` / `treeGrid` / `pager` / `filters` — форма списку.
- **`group` — редактори запису, `tab` — рядки колекції.** `scope` пишеться **лише на `tab`** і там обов'язковий; `tab` — лише всередині `tabs`. Колекція без видів — смуга з одним табом. Слів `table` / `grid` / `checkbox` у мові немає.
- **`kind`** — для колекції, що оголосила види ([metadata.md](metadata.md) → «`kinds` — види рядків»): обов'язковий тоді і тільки тоді. Складене ім'я (`scope: "StockRows"`) не приймається — пишуть дві частини:

```json
{ "is": "tab", "scope": "Rows", "kind": "Stock" }
```

## Форма запису — `body`

```json
"forms": {
  "edit": {
    "is": "page",
    "taskpad": { "is": "taskpad",
      "elements": [ { "is": "group", "fields": ["Company", "Project"] } ] },
    "body": [
      { "is": "group", "fields": ["Number", "Date"] },
      { "is": "group", "axis": "rows", "fields": ["Agent", "StoreFrom", "StoreTo"] },
      { "is": "group", "axis": "rows", "fields": ["IsVat", "VatIncluded"] },
      { "is": "tabs",
        "elements": [
          { "is": "tab", "scope": "Rows", "kind": "Stock" },
          { "is": "tab", "scope": "Rows", "kind": "Service", "fields": ["Item", "Sum"] }
        ] },
      { "is": "group", "fields": ["Memo"] }
    ]
  }
}
```

- **`body` — вертикальний стек вузлів**; `axis` у корені немає. Групи вкладаються: у групі спершу йдуть `fields`, потім `elements`.
- **Розтяжку ніхто не оголошує:** блок `tabs` забирає вільну висоту; таких блоків нуль або один, два — помилка збірки. «Memo внизу» — наслідок того, що він **після** `tabs`.
- **`tabs` пишеться явно** — інакше вкладену колекцію не показати.
- **Іменованих регіонів (`header` / `footer` / `above` / `below`) немає.**
- Одна смуга може тримати кілька колекцій і види однієї. **Один row set у двох табах** однієї смуги і **смуга без табів** — помилка.
- Чекбоксів на самій смузі табів немає: вони йдуть у звичайну групу перед смугою.

## Форма списку — `dataGrid` / `pager` / `filters`

```json
"forms": {
  "index": {
    "body": [
      { "is": "dataGrid", "fields": ["Name", "Agent", "Date", "Sum"] },
      { "is": "pager" }
    ],
    "taskpad": { "is": "taskpad",
      "elements": [ { "is": "filters", "filters": ["Period", "Agent"] } ] }
  }
}
```

- **`dataGrid`** — таблиця кореневої колекції; `fields` дає склад і **порядок** колонок. Ширину, роль і формат колонки несе домен. Грид забирає вільну висоту; пейджер унизу тому, що він **після** грида.
- **`pager`** — вузол без ключів; показує сторінки (запит сторінковий завжди). Пишеться в `index`; у `browse` пейджер, рамку, кнопки вибору й подвійний клік ставить шаблон діалогу.
- **`treeGrid`** замість `dataGrid` — дерево приходить цілком: пейджера, фільтрів і пошуку в нього немає. Дані дерева сьогодні отримує лише `accplan` ([accplan.md](accplan.md) → «Екрани»); `treeGrid` у формі іншого kind-а порожній.
- **Сортування й пошук не оголошуються:** грид сортує сам (set-посилання не сортується), пошук і кнопка `Search` є завжди.
- `browse` — та сама форма: грид і фасети ті самі.

### Панель фасетів

Малює її **лише** вузол `filters` у `elements` таскпада:

```json
"taskpad": {
  "is": "taskpad",
  "elements": [
    { "is": "filters", "filters": [ "HeadCounterparty", "PrimaryCounterpartyContract" ] }
  ]
}
```

Ключ `filters` на `dataGrid` чи на самому `taskpad` — помилка. Вузла `filters` без фільтрів не буває.

### `filters` — окремий namespace, а не поля

Імена фільтрів виводяться з shape і декларації endpoint'а; блоку `filters` на рівні endpoint'а немає. Склад рівно такий:

| Звідки | Ім'я фільтра | Є коли |
|---|---|---|
| період | `Period` | kind — `document`, `journal` або `ledger` |
| кожне посилальне поле | ім'я поля | тип поля посилальний: `ref`, `enum`, `state`, `user`, `company`, `owner`, `basedOn`, `account`, `document`, master |
| поле типу `operation` | ім'я поля | на власнику таблиці — по всіх операціях; на документі з `operations` — «Усі операції» + його операції; на документі над `storage` без `operations` — **немає** |
| роль стану | `<Поле>Role` | поле типу `state` — друге ім'я на ту саму колонку (стадія циклу, а не стан) |
| trait `tags` | `Tags` | оголошено trait |

Нічого більше: дата, рядок, число й `boolean` фільтра не дають; на catalog фільтра за періодом немає. Дефолтна панель показує лише перше з двох імен state-поля; `<Поле>Role` — тільки в оголошеній формі.

Форма може фільтр **сховати, ніколи — вигадати**: ім'я поза простором падає при завантаженні з переліком доступних. **Звуження панелі не звужує запит** — прибраний фільтр зникає з екрана, а не з `WHERE`.

## Ключі вузлів

| що | ключі дітей | елемент |
|---|---|---|
| корінь форми (`index` / `browse` / `edit`) | `body` + `toolbar` + `taskpad` | вузол / слот |
| `group` | `fields` + `elements` | ім'я поля / вузол |
| `tabs` | `elements` — **тільки таби, не менше одного** | вузол |
| `tab` | `scope` (+`kind`) — обов'язковий; `fields` — опційний (відсутній = весь рядок у порядку metadata) | ім'я поля |
| `dataGrid` / `treeGrid` | `fields` | ім'я колонки |
| `taskpad` | `elements` | вузол |
| `filters` | `filters` | ім'я фільтра |
| `toolbar` | `commands` | ім'я команди |
| `pager` | — | — |

- **Ключ не своєї ролі — помилка** (`filters` на гриді, `fields` на смузі табів).
- 🟡 **Виняток — `tab`:** `filters` / `commands` / `elements` на ньому проходять і не малюють нічого. Не писати.
- `body`, `elements` групи й таскпада приймають будь-яку роль, крім `tab`; `elements` смуги — **тільки** `tab`.
- `fields` — плаский масив імен, без вкладеності й без коми в імені (`["Company, Project"]` — одне поле з комою, помилка).
- `commands` — регістр значущий: `Save`, не `save`.

## Toolbar

**Стандартний набір команд не пишеться** — виводиться з ролі форми, kind і metadata: `Post` / `UnPost` / `ShowTrans` — з непорожнього `post` (`ShowTrans` — діалог рухів документа: у які журнали і на які суми він проводить), `Print` — з `printForms` ([print.md](print.md)), `BasedOn` — з `basedOn` ([metadata.md](metadata.md) → `basedOn`). Вимкнути стандартну команду не можна; не потрібна → eject.

Слот `toolbar` тримає лише **додані** команди. Їхнє місце обирає шаблон — між командами сутності і хвостом (`Reload`, `Search`); від стандартних їх відділяє сам шаблон, тож `$sep` пишеться лише між доданими, не першим. Стандартне ім'я в слоті дає другу кнопку.

Словник команд замкнутий: `Create`, `Edit`, `Delete`, `Save`, `SaveAndClose`, `Print`, `BasedOn`, `Copy`, `Show`, `ShowTrans`, `Search`, `Reload`, `Post`, `UnPost`, `Attachments` + `$sep`.

**`toolbar` у `body` — друга смуга**, лише власні команди. `toolbar` у `edit` з `is: "dialog"` — помилка: у діалозі смуги немає.

🟡 Власних команд немає: ім'я в слоті поки ні на що, крім словника вище, не посилається.

## Розкрій — `axis`

Група — потокова смуга. Без `axis` поля стікаються стовпчиком, з `"axis": "rows"` — йдуть смугою вправо й переносяться, коли не влазять:

```json
{ "is": "group", "fields": [...] }
{ "is": "group", "axis": "rows", "fields": [...] }
```

| Ключ | Тип | Умовчання |
|---|---|---|
| `axis` | `"columns"` \| `"rows"` | `"columns"` |

**Ширин, спанів, числа колонок, порядку обходу й точок переносу в мові немає.** Ширину й розтяжність кожного поля дає його домен; «три колонки» виходять самі, коли в смузі три поля, а вікно ширше. Нерівний рядок = **окрема група**. Вирівнювання між рядами немає: у смузі однакових доменів краї збігаються самі, у різнорідній будуть рваними.

## Ширина і розтяжність — властивість домену

У формі не оголошуються **взагалі**: генератор ставить на контрол клас домену, значення живуть у стилях платформи (`Memo` тягнеться й забирає решту смуги, `Date` не росте, `Ref` не стискається).

## `labelAt`

Де стоїть підпис відносно контрола; ортогональне до розкрою.

```json
{ "is": "group", "axis": "rows", "labelAt": "left", "fields": ["Number", "Date", "ExtNumber"] }
{ "is": "group", "axis": "rows", "fields": ["Agent", "Contract", "Role"] }
```

| Ключ | Тип | Умовчання |
|---|---|---|
| `labelAt` | `"top"` \| `"left"` | `"top"` |

- **Властивість смуги, не поля:** усередині смуги підписи стоять однаково.
- **Не успадковується.** Успадковується тільки `scope`; усе, що про вигляд, вузол оголошує сам.
- Ширини підпису немає; при `"left"` довгий підпис витискає ввід. Підписи сусідніх рядків не вирівнюються — лікується `"top"`.

## 🚧 `title`

Заголовок групи — ключ `title` (ключ локалізації) — у схемі й у типі вузла немає: не писати.

## Що падає гучно, а що ні

Усі три форми резолвляться при **завантаженні endpoint'а** — помилку дає `a2 meta validate` ([validate.md](validate.md)), а не перший запуск сторінки. Повідомлення називає форму (`form 'edit': …`).

Падає при завантаженні:
- невідоме поле, невідомий фільтр (з переліком доступних), зайвий ключ у `forms`;
- `scope` не на табі, таб поза смугою, не-таб у смузі, таб без `scope`, смуга без табів, один row set у двох табах однієї смуги;
- ключ, якого роль не читає;
- `toolbar` на `edit`-діалозі.

Завантажувач мовчить, ловить лише схема — у редакторі й стадія `schema` у `a2 meta validate` (version >= 8670):
- невідома властивість вузла (`labelat` замість `labelAt`; `is` чи `scope` у корені `index`);
- `axis` / `labelAt` не на групі;
- вузол без `is` — завантажувач робить із нього групу.

🟡 Невідоме значення `is` падає без імені форми й файла: `Requested value 'sparkline' was not found.`

## `readonly` — не в моделі взагалі

Редагованість запису цілком — прапор, який приходить із **кожною** відповіддю (права, стан): той самий документ буває редагований чи ні. Ні форма, ні metadata про нього не знають, окремої форми перегляду немає. Не плутати з **польовою** нередагованістю — поле під властивістю без `set` чи з `sqlAs` (вище, «Чи можна вводити»).

## Чого в мові немає і не буде

- **Об'єкти на полі** (`{ "field": "Sum", "readonly": true }`) — це домени; чинити `fields`.
- **`required` на полі форми** — блок `rules` у metadata ([rules.md](rules.md)).
- **Контроли** (`checkbox`, `table`, `controls`) — виводяться з домену.
- **Caption панелей як вільний текст** — локалізація.
- **`grid.row`, ширини, спани, розкладка окремого поля.**
- **Окрема «форма перегляду»** — див. `readonly`.
- **Рядок підсумків у гриді** 🟡 — `rules.total` дає суму на колекції ([rules.md](rules.md)), але форма її не малює.
