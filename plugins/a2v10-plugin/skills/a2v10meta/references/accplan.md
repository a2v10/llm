# accplan — план рахунків

Kind `accplan`: план рахунків (chart of accounts). Таблиця, ключ якої — **код рахунку**, рядки якої оголошує файл застосунку і пише деплой. Проводки на рахунки — окремий kind, [ledger.md](ledger.md).

## Файли

```
accplan/<name>/metadata.json
accplan/<name>/seed.json
```

**План завжди іменований**, навіть єдиний: `/accplan/national`. Голої форми `accplan/metadata.json` немає — у одного факту було б два написання, а поява другого плану переносила б перший разом з усіма посиланнями на нього. Кілька планів — кілька endpoint-ів, кожен зі своєю таблицею (`/accplan/national`, `/accplan/ifrs`).

```jsonc
// accplan/national/metadata.json
{
  "$schema": "../../@schemas/metadata-accplan-json-schema.json#",
  "table": "National",
  "model": "Account",
  "seed": "seed.json"
}
```

| Ключ | Required | Призначення |
|---|---|---|
| `table` | ✅ | Ім'я таблиці, як у будь-якого endpoint-а. Схема — `acc` |
| `seed` | ✅ | Ім'я файла рядків у теці endpoint-а. З наявності файла нічого не виводиться — ключ пишеться завжди |
| `model` | ⚪ | Основа згенерованих імен: колекція, тип, заголовок картки. Умовчання — ім'я теки (`national` → `National`); для плану пишеться `Account` → `Accounts` / `TAccount` |
| `fields` | ⚪ | Поля автора поруч із baseline — як у catalog |
| `forms` | ⚪ | [forms.md](forms.md) |

`storage` і `surface` не пишуться.

## Baseline

| Поле | Що це |
|---|---|
| `Id` | `nvarchar(64)` PK — **код рахунку**. Окремої колонки `Code` немає: код і є ключ |
| `Name` | назва |
| `Parent` | self-FK на `Id`, `null` = корінь. **Єдиний носій дерева** — з коду не виводиться: префіксність (36 → 361) — угода конкретного плану, не платформи |
| `AccountType` | розділ звітності: `Asset` / `Liability` / `Equity` / `Income` / `Expense` / `OffBalance` |
| `NormalBalance` | сторона сальдо: `Debit` / `Credit` / `Both` |
| `Void` | рахунок закрито для вибору |
| `IsSystem` | рахунок із файла; пише деплой |
| `RowVersion`, штампи | як у catalog |

`AccountType` і `NormalBalance` — закриті набори платформи, зберігаються **іменем**, `nvarchar(16)` без CHECK. Дві осі, два поля: `NormalBalance` з `AccountType` не виводиться (знос 131 — `Asset` з `Credit`). Забалансовий рахунок — значення `OffBalance`, не окремий прапор.

**Решта ознак рахунку — `fields` автора** (валютний, кількісний, «рахунок для проводок»): що читає платформа — baseline, що читають лише операції автора — `fields`.

## `seed.json` — рядки плану

Мапа «код → колонки»:

```jsonc
// accplan/national/seed.json
{
  "28":  { "Name": "Товари", "AccountType": "Asset", "NormalBalance": "Debit" },
  "281": { "Name": "Товари на складі", "AccountType": "Asset", "NormalBalance": "Debit", "Parent": "28" }
}
```

- ключ — код; дубль коду невиразний;
- значення — колонки **під своїми іменами**: baseline `Name`, `Parent`, `AccountType`, `NormalBalance` і поля автора;
- `Name`, `AccountType`, `NormalBalance` — обов'язкові в кожному рядку; `AccountType` / `NormalBalance` пишуться точно як ім'я значення (`Asset`, не `asset`);
- `Parent` — код **з цього ж файла**; циклів немає; відсутній `Parent` = корінь;
- `Id`, `IsSystem`, `Void`, `RowVersion`, штампи не пишуться — їх пише платформа;
- **у коді заборонена `.`** — роздільник зарезервований під субрахунки користувача (`361.1`), щоб реліз не міг оголосити код, який користувач уже завів; довжина коду — до 64;
- значення — скаляр, що підходить колонці; посилання (`ref`) у файлі не пишуться.
- `Name` — просто рядок; `"@[Acc.281]"` розкриє локалізатор при показі.

Усе перевіряється **при завантаженні**, без БД; порушення — помилка з кодом рахунку й іменем колонки. `seed` на будь-якому іншому kind-і — теж помилка при завантаженні: ключ поки обробляє лише `accplan`.

## Деплой: план — конфігурація

Рахунки з файла — **конфігурація застосунку**: на них посилається код, тож правити їх не може ніхто. Деплой зводить файл у таблицю одним merge:

| Стан | Що робить деплой |
|---|---|
| рядок є у файлі | `IsSystem = 1`, `Void = 0`, колонки, які рядок називає. Поле автора, якого рядок **не називає**, не чіпається |
| рядок прибрали з файла | рядок лишається (на нього тримають FK), `IsSystem = 0`, `Void = 1` — закритий для вибору; знадобиться — відкриє бухгалтер |
| рядок повернули у файл | відновлюється тим самим ходом: `IsSystem = 1`, `Void = 0` |
| `IsSystem = 0` і у файлі його немає | не чіпається |

Зміна `seed.json` — привід для деплою сама по собі: рядки входять у хеш.

**`IsSystem = 1` — запис тільки для читання.** Це загальне правило платформи для таблиці з колонкою `IsSystem`, не особливість плану: картка такого запису відкривається read-only.

🚧 **Рахунків користувача немає.** Прийнята форма — субрахунок під рахунком файла, код = код батька + `.` + суфікс (`361.1`), `Parent` незмінний; створення платформа не виконує, у v1 план складається лише з рядків файла.

## Екрани

- **index** — дерево (`treeGrid`, [forms.md](forms.md)): колонки `Код`, `Name`, `AccountType`, `NormalBalance`; `Parent` колонкою не показується — його показує дерево. Читається цілком, батьки перед дітьми; без пейджера, фільтрів і пошуку. Смуга — `Edit` і `Reload`: створювати й видаляти нічого.
- **edit** — звичайна картка-діалог, для рахунку з файла — тільки для читання. `AccountType` / `NormalBalance` — випадні списки закритих наборів.

`Parent` у моделі даних зветься **`ParentElem`** (`Account.ParentElem`): `Parent` — зарезервоване слово моделі. Колонка в БД і ключ у `seed.json` — `Parent`. Для форми (`fields`) ім'я поля — `Parent`.

**Локалізація**, яку дає застосунок ([localization.md](localization.md)):

| Ключ | Де |
|---|---|
| `@[Code]` | заголовок коду (натуральний ключ — не `#`) |
| `@[Name]`, `@[Parent]`, `@[AccountType]`, `@[NormalBalance]` | підписи полів |
| `@[AccountType.Asset]` … `@[AccountType.OffBalance]` | значення розділу — всі шість |
| `@[NormalBalance.Debit]`, `@[NormalBalance.Credit]`, `@[NormalBalance.Both]` | значення сторони сальдо |
| `@[<model>]` | заголовок картки: `@[Account] [361]` |

**Меню:** план — самостійний вхід, пункт `/accplan/<name>` ([menu.md](menu.md)).

## Посилання на рахунок

Домен `Account` — поле, що посилається на рахунок:

```jsonc
"Account": { "type": "account", "target": "/accplan/national" }
```

- `target` — план рахунків, обов'язковий; шлях не на `accplan` — помилка при завантаженні. `Ref` на план не пишеться: `Ref` — завжди `platformid`, а ключ плану — код;
- **вибір — деревом плану**: діалог `browse` показує те саме дерево, що index, без закритих рахунків (`Void`); вибирається будь-який вузол, і група теж;
- **показ і пошук при вводі — за `presentation` плану**, тобто за кодом;
- фільтр списку за такою колонкою — вибір рахунку, як у `Ref`;
- `inherit` працює як для будь-якого посилання.

🚧 **Збереження значення** поля `Account` не реалізоване. 🚧 **`subtree`** — сужування вибору піддеревом (фільтр вибору + перевірка при збереженні) — відкладено.
