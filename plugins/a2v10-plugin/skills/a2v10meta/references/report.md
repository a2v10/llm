# report — звіти

Kind `report`, схема `rep`. Власних даних не має: це **вікно в поверхню** — запит плюс презентація.

## Формула

**Звіт = поверхня × сабсет × форма (+ вибір клієнта в рантаймі).**

| Вісь | Питання | Хто задає |
|---|---|---|
| Поверхня | що взагалі можна спитати | той, на кого вказує `surface` |
| Сабсет | що запропоновано людині | `metadata.json` звіту |
| Форма | як відповідь лягає на екран | `type` звіту |
| Вибір | що спитано зараз | клієнт, рантайм |

**Звіт фіксує простір запитів, а не запит.** «Оборотка по складу» — не один SELECT: із сабсета {Store, Item} × {Qty, Sum} комбінаторно виходить багато легальних запитів (галочки, порядок, фільтри, період), і жоден із них не «головний». Заморожено лише сабсет і дефолти.

Звуження двоступеневе: **поверхня ⊇ сабсет ⊇ запит.** Перше перевіряється на збірці (кожне ім'я сабсета резолвиться в поверхню), друге — в рантаймі (вибір клієнта ⊆ сабсет).

## Формат

```jsonc
// report/stockturnover/metadata.json
{
  "type": "turnover",
  "surface": "/journal/stock",
  "groups":  ["Store", "Item"],
  "filters": ["Store", "Item"],
  "data":    ["Qty", "Sum"],
  "defaults": { "groups": ["Store"], "data": ["Qty", "Sum"] }
}
```

| Ключ | Required | Тип | Призначення |
|---|---|---|---|
| `type` | ✅ | string | Форма звіту: `"turnover"` — залишок на початок + обороти + залишок на кінець у вибраних групуваннях; `"trialBalance"` — оборотно-сальдова відомість ledger-а; `"chessboard"` — шахова відомість ledger-а (нижче) |
| `surface` | ✅ | string | Поверхня: журнал для `turnover`, ledger для `trialBalance` і `chessboard` |
| `groups` | ⚪ | string[] | Виміри, доступні для групування. Порядок = порядок у taskpad |
| `filters` | ⚪ | string[] | Виміри, доступні для фільтрації |
| `data` | ⚪ | string[] | Міри, доступні для показу |
| `defaults` | ⚪ | object | Що відмічено при відкритті: `groups` / `data` — підмножини відповідних списків |

**`surface`, а не `storage`.** `storage` означає протилежне: «мої рядки лежать у чужій таблиці, і я успадковую її декларацію». Звіт не має рядків і не успадковує нічого. Звіт, що написав `table` чи `storage`, — помилка збірки, як і звіт без `surface`.

**Порядок несе семантику** — окремого `order` немає, порядок у списку і є порядок.

**`defaults` — не окремий вид елемента.** Це підмножина вже перелічених імен; ім'я, якого немає у відповідному списку, — помилка збірки.

## `trialBalance` — оборотно-сальдова відомість

```jsonc
// report/trialbalance/metadata.json
{
  "type": "trialBalance",
  "surface": "/ledger/national",
  "filters": []
}
```

По рахунках ledger-а ([ledger.md](ledger.md)): сальдо на початок, обороти Дт / Кт за період, сальдо на кінець — кожне сальдо парою Дт / Кт.

- **Вибору немає, крім періоду й `filters`.** Групування — `Acc`, міра — `Sum`, обидва з baseline ledger-а; `groups`, `data`, `defaults` не пишуться. Інакше звіт не сходиться.
- `filters` — виміри ledger-а, як у `turnover` (напр. `Company`, коли він є); порожній список — законно.
- **Сальдо розкладається за `NormalBalance` рахунку** ([accplan.md](accplan.md)), не за знаком: `Debit` — завжди в дебеті, мінус лишається мінусом; `Credit` — дзеркально; `Both` — за знаком. Розклад — по рахунку, потім сума: рядок «Всього» — сума пар, не розклад знакової суми.
- Рядки — рахунки, на яких є проводки до кінця періоду, за кодом; ієрархії плану (28 над 281) немає.
- `surface` не на ledger — помилка при відкритті звіту.

**Локалізація**, яку дає застосунок: `@[TrialBalance]`, `@[TrialBalance.Start]`, `@[TrialBalance.Turnover]`, `@[TrialBalance.End]`, `@[Account]`, `@[Code]`, `@[Name]`, `@[Debit]`, `@[Credit]`, `@[Total]`.

## `chessboard` — шахова відомість

```jsonc
// report/chessboard/metadata.json
{
  "type": "chessboard",
  "surface": "/ledger/national",
  "filters": []
}
```

Обороти ledger-а за період у кореспонденції рахунків: рядки — рахунки дебету, колонки — рахунки кредиту, у клітинці — оборот `Дт рядка — Кт колонки`.

- **Вибору немає, крім періоду й `filters`** — як у `trialBalance`: `groups`, `data`, `defaults` не пишуться.
- **Читаються лише дебетові плечі** (`InOut = +1`): кожна проводка там рівно один раз, `Acc` × `CorrAcc`. Підсумок рядка — оборот Дт рахунку, підсумок колонки — оборот Кт.
- **Колонки — дані:** набір кореспондуючих рахунків за період; ключ колонки — код рахунку.
- Рядки й колонки — лише рахунки з оборотом за період, за кодом; ієрархії плану немає.
- `surface` не на ledger — помилка при відкритті звіту.

**Локалізація**, яку дає застосунок: `@[Chessboard]`, `@[Chessboard.Header]` (шапка над колонками — «З дебету в кредит рахунків»), `@[Code]`, `@[Name]`, `@[Total]`.

## Що в metadata звіту НЕ пишеться

- **Presentation.** Колонки, шапки, тотал-рядок, кольори семантик, розгортка знакових мір у пари Дт/Кт — **чиста функція** від (міри × семантики × групування). Рендерер платформи це виводить; декларувати нічого.
- **Label / заголовки** — локалізація.
- **Сам запит.** Звіт не містить SQL і не містить вибору; вибір робить клієнт у межах сабсета.
- **Збережений вибір користувача** — це profile-патерн, не metadata і не сабсет.

Нерегулярний звіт → **eject** у рукописний хендлер (`IEndpointHandler` + `DynamicRenderer`), як і всюди: континуум матеріалізації, без лазівок у форматі.
