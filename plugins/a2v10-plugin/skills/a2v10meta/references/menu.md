# Меню — навігація застосунку

`MainApp/menu.json` — єдине місце, де endpoint отримує **самостійний вхід**: екран, на який користувач заходить сам, а не з-під чужої форми. Без пункту меню endpoint нікуди не дівається — довідник і далі відкривається лукапом Ref-поля, там же створюють і редагують записи, — але до його реєстру користувача не веде ніщо.

## Конверт

```json
{
  "$schema": "@schemas/menu-json-schema.json#",
  "appTitle": "Склад",
  "columns": 3,
  "menu": []
}
```

`menu` — **масив** розділів. `appTitle` — те, що бачить користувач у заголовку; це не ім'я застосунку (папка / проект / БД), і збігатися вони не зобов'язані. `columns` — число колонок сітки, в якій сторінка розділу розкладає підрозділи; одне на весь застосунок, без ключа — 1.

## Роль дає позиція

У JSON тип вузла один — і саме тому легко прочитати, що ключі можна ставити де завгодно. Не можна: **роль вузла задає глибина**, і кожна роль має власний набір ключів. Позицій рівно чотири, довільної вкладеності немає.

| Рівень | Роль | Що це на екрані | Ключі |
|---|---|---|---|
| 1 | **Розділ** — Продажі, Закупівлі, Склад | Кнопка у вертикальній смузі зліва | `title`, `icon`, `items`, `underline`, `roles` |
| 2 | **Підрозділ** — Документи / Довідники / Звіти | Заголовок групи на сторінці розділу | `title`, `items`, `row`, `col` |
| 3 | **Пункт** | Посилання в групі | `title`, `url`, `create` |
| 3 + `items` | **aux** | Пункт, що відкриває двопанельний браузер | `title`, `id`, `items` |
| 4 | Вміст aux | Рядок у браузері | `title`, `url`, `category` |

Ключ не зі свого рівня не читається — **тихо, без помилки**. Тому кожен має рівно одне місце:

- `title` — єдиний спільний для всіх. `@[Key]` — ключ локалізації ([localization.md](localization.md)), інакше літерал;
- `icon` — тільки розділ, бо смуга зліва — єдине місце, де іконка малюється. Словник закритий, невідоме ім'я мовчки не малюється — не вгадувати; повний список → [app/menu.md#icons](https://docs-llm.a2v10.com/app/menu.md#icons);
- `url` — тільки лист (3 або 4). Розділ і підрозділ ведуть у свій вміст, а не в endpoint, і посилання не несуть;
- `underline` і розпірка — тільки розділ: вони про смугу;
- `roles` — тільки розділ: чиє це робоче місце (ключі `roles` з `app.json` або `Everyone`). Діє лише при `useGrants: true` (version >= 8670) — нижче;
- `row`, `col` — тільки підрозділ: клітинка його групи в сітці сторінки розділу, з 1, як CSS `grid-row` / `grid-column`; ширина сітки — `columns` у конверті. Без них — авторозкладка CSS grid: у порядку масиву, зліва направо, `columns` в ряд, у вільні клітинки;
- `id` — тільки aux, `category` — тільки його вміст;
- `create` (`boolean`) — тільки лист рівня 3: поруч із пунктом кнопка «Створити», що відкриває діалог нового запису (`{url}/edit/new`). Для довідників і документів, які заводять просто з меню.

Порядок на кожному рівні — порядок у масиві, іншого немає. Одна сутність може стояти в кількох розділах — це не дубль.

Права на пункт тут не пишуться: кому пункт видно, вирішує `CanView` на його endpoint-і, а розділ живий, доки в ньому лишилась видима дитина ([permissions.md](permissions.md) → «Меню виводиться з прав»). Розділ відповідає ще на одне питання — **чиє це робоче місце**: `"roles": ["Accountant"]` ховає «Бухгалтерію» від комірника, хоч довідник компаній із неї відкритий усім (`Everyone` — щоб працював пікер). Без `roles` розділ — для всіх, кому в ньому є що показати. Компанії потрібні комірнику пунктом меню — їх ставлять і в його розділ. Фільтр працює лише при `useGrants: true` (version >= 8670); без нього `menu.json` показується цілком і всім. Меню ховає, а не забороняє: прихований пункт досяжний за URL.

## Розпірка

Порожній вузол, який нічого не показує:

```json
{ "grow": true }
```

Стоїть у масиві розділів; усі розділи після нього віджимаються в кінець смуги — так відсувають «Налаштування» вниз.

## `url` — рівно те, що пишеться всюди

У меню пишеться `/<kind>/<endpoint>`; endpoint у теці-аліасі — `/<аліас>/<endpoint>` (`/sale/invoice`, [kinds.md](kinds.md) → «Аліаси kind-а»). Модульний префікс працює: `/$meta/config`, `/$workflow/catalog`.

Що потрапляє в меню:

| Endpoint | В меню |
|---|---|
| `catalog`, `journal`, `report`, `accplan`, `ledger` | так |
| документ (`/document/waybillin`, `/document/receipt`) | так |
| корінь спільної таблиці (`/document`) | за потреби — реєстр усіх документів над нею ([kinds.md](kinds.md) → «Адресація»); при `useGrants` — зі своїм `grants` у `document/metadata.json`, гранти документів він не успадковує |
| операція документа | ніколи — операцію перемикають у відкритому документі, адреси в неї немає ([metadata.md](metadata.md) → «`document` — таблиця й операції») |

`autonum` і `enum` — у меню **не потрапляють**: свого екрана в них немає; ролі (`app.json` → `roles`, [permissions.md](permissions.md)) — теж. У `autonum` паттерн і період задає файл, а лічильники редагувати нікому; значення `enum` приїжджають з тим екраном, який на них указує ([kinds.md](kinds.md)).

## aux — двопанельний браузер

Купа дрібних довідників (одиниці, країни, валюти) не заслуговує окремих пунктів. Тригер — **не спеціальний URL, а форма**: вузол третього рівня, у якого є `items`.

```json
{ "title": "@[OtherCatalogs]", "id": "misc",
  "items": [
    { "title": "@[Units]",     "url": "/catalog/unit",     "category": "@[General]" },
    { "title": "@[Countries]", "url": "/catalog/country",  "category": "@[General]" }
  ]
}
```

`id` — ключ сторінки (`/_auxmenu/any?mode={id}`), тому він тут обов'язковий. Діти в меню **не рендеряться** — їх показує сама сторінка; `category` групує їх на ній і поза aux не читається взагалі.

## Робота з файлом

**Завжди читай `menu.json` перед зміною** — він єдиний і його правлять руками.

- новий endpoint → пункт у відповідний підрозділ потрібного розділу; розділ не названий — спитай, а не вгадуй;
- розділу ще немає → заводиться разом із `title` та `icon`;
- прибрати з меню = прибрати пункт; endpoint при цьому лишається на місці й доступний за URL.
