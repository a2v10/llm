# Меню — навігація застосунку

`MainApp/menu.json` — єдине місце, де endpoint отримує **самостійний вхід**: екран, на який користувач заходить сам, а не з-під чужої форми. Без пункту меню endpoint нікуди не дівається — довідник і далі відкривається лукапом Ref-поля, там же створюють і редагують записи, — але до його реєстру користувача не веде ніщо.

## Конверт

```jsonc
{
  "$schema": "@schemas/menu-json-schema.json#",
  "appTitle": "Склад",
  "menu": [ /* розділи */ ]
}
```

`menu` — **масив**. `appTitle` — те, що бачить користувач у заголовку; це не ім'я застосунку (папка / проект / БД), і збігатися вони не зобов'язані.

## Роль дає позиція

У JSON тип вузла один — і саме тому легко прочитати, що ключі можна ставити де завгодно. Не можна: **роль вузла задає глибина**, і кожна роль має власний набір ключів. Позицій рівно чотири, довільної вкладеності немає.

| Рівень | Роль | Що це на екрані | Ключі |
|---|---|---|---|
| 1 | **Розділ** — Продажі, Закупівлі, Склад | Кнопка у вертикальній смузі зліва | `title`, `icon`, `items`, `underline` |
| 2 | **Підрозділ** — Документи / Довідники / Звіти | Заголовок групи на сторінці розділу | `title`, `items` |
| 3 | **Пункт** | Посилання в групі | `title`, `url`, `create` |
| 3 + `items` | **aux** | Пункт, що відкриває двопанельний браузер | `title`, `id`, `items` |
| 4 | Вміст aux | Рядок у браузері | `title`, `url`, `category` |

Ключ не зі свого рівня не читається — **тихо, без помилки**. Тому кожен має рівно одне місце:

- `title` — єдиний спільний для всіх. `@[Key]` — ключ локалізації ([localization.md](localization.md)), інакше літерал;
- `icon` — тільки розділ, бо смуга зліва — єдине місце, де іконка малюється. Словник закритий, невідоме ім'я мовчки не малюється — не вгадувати; повний список → [app/menu.md#icons](https://docs-llm.a2v10.com/app/menu.md#icons);
- `url` — тільки лист (3 або 4). Розділ і підрозділ ведуть у свій вміст, а не в endpoint, і посилання не несуть;
- `underline` і розпірка — тільки розділ: вони про смугу;
- `id` — тільки aux, `category` — тільки його вміст;
- 🟡 `create` (`boolean`) — є у схемі меню і стоїть у стенді на листах-довідниках і на документах, що створюються з меню. Читає його клієнтська оболонка; у C#-коді платформи він не зустрічається, тож що саме вмикає — тут не зафіксовано. Не ставити навмання.

Порядок на кожному рівні — порядок у масиві, іншого немає. Одна сутність може стояти в кількох розділах — це не дубль.

Ключа про права тут немає й не буде: кому пункт видно, вирішує `CanView` на його endpoint-і, а розділ живий, доки в ньому лишилась видима дитина ([permissions.md](permissions.md)). 🚧 Самого фільтра ще немає — `menu.json` сьогодні показується цілком і всім; ключ від цього не з'являється, але й обіцяти, що пункт від когось сховається, не можна.

## Розпірка

Порожній вузол, який нічого не показує:

```jsonc
{ "grow": true }
```

Стоїть у масиві розділів; усі розділи після нього віджимаються в кінець смуги — так відсувають «Налаштування» вниз.

## `url` — рівно те, що пишеться всюди

У меню пишеться `/<kind>/<endpoint>`. Модульний префікс працює: `/$meta/config`, `/$workflow/catalog`.

Що потрапляє в меню:

| Endpoint | В меню |
|---|---|
| `catalog`, `journal`, `report`, `accplan`, `ledger` | так |
| **операція** документа (`/document/waybillin`) | так |
| **база** родини (`document/metadata.json`) | ніколи — адреси не має ([kinds.md](kinds.md) → «Адресація») |

`autonum`, `enum` і `roles` (🚧, [kinds.md](kinds.md)) — у меню **не потрапляють**: свого екрана в них немає. У `autonum` паттерн і період задає файл, а лічильники редагувати нікому; значення `enum` приїжджають з тим екраном, який на них указує ([kinds.md](kinds.md)).

## aux — двопанельний браузер

Купа дрібних довідників (одиниці, країни, валюти) не заслуговує окремих пунктів. Тригер — **не спеціальний URL, а форма**: вузол третього рівня, у якого є `items`.

```jsonc
{ "title": "@[OtherCatalogs]", "id": "misc",
  "items": [
    { "title": "@[Units]",     "url": "/catalog/unit",     "category": "@[General]" },
    { "title": "@[Countries]", "url": "/catalog/country",  "category": "@[General]" }
  ]
}
```

`id` — ключ сторінки (`/_auxmenu/any?mode={id}`), тому він тут обов'язковий. Діти в меню **не рендеряться** — їх показує сама сторінка; `category` групує їх на ній і поза aux не читається взагалі.

## Робота з файлом

**Завжди читай `menu.json` перед зміною** — він єдиний і його правлять руками.

- новий endpoint → пункт у відповідний підрозділ потрібного розділу; розділ не названий — спитай, а не вгадуй;
- розділу ще немає → заводиться разом із `title` та `icon`;
- прибрати з меню = прибрати пункт; endpoint при цьому лишається на місці й доступний за URL.
