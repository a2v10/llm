# ledger — бухгалтерські проводки

Kind `ledger`: проводки на рахунки одного плану ([accplan.md](accplan.md)). Пишеться **тільки через `post`** документа, як журнал; власного вводу немає. Проводка лежить **дзеркальними плечима**: рядок на дебет, рядок на кредит, `CorrAcc` кожного — `Acc` протилежного.

Не `journal` із двома полями рахунку: **аналітика належить плечу** (номенклатура — дебету 281, постачальник — кредиту 631), і в журнальному форматі сказати «`Agent` — аналітика кредитового плеча» немає де.

## Файли

```
ledger/<name>/metadata.json
```

```jsonc
// ledger/national/metadata.json
{
  "$schema": "../../@schemas/metadata-ledger-json-schema.json#",
  "table": "National",
  "model": "Entry",
  "accplan": "/accplan/national",
  "fields": {
    "Document":  { "type": "document", "target": "/document" },
    "Operation": { "type": "operation" },
    "Row":       { "type": "row" },
    "Item":      { "type": "ref", "target": "/catalog/item" },
    "Qty":       { "type": "qty" },
    "Store":     { "type": "ref", "target": "/catalog/store" },
    "Agent":     { "type": "ref", "target": "/catalog/agent" }
  }
}
```

| Ключ | Required | Призначення |
|---|---|---|
| `table` | ✅ | Ім'я таблиці. Схема — `led` |
| `accplan` | ✅ | План, на який проводить ledger: ціль `Acc` і `CorrAcc`. Умовчання немає — `ledger/national` → `accplan/national` не виводиться. Шлях не на `accplan` — помилка при завантаженні; ключ на іншому kind-і — теж |
| `model` | ⚪ | Основа згенерованих імен, як у будь-якого endpoint-а. Умовчання — ім'я теки |
| `fields` | ✅ | Походження, аналітика, міри |
| `forms` | ⚪ | [forms.md](forms.md) |

**Один ledger — один план.** Колонки плану в рядку немає: кожен FK став би складеним. На одному плані законні кілька ledger-ів (факт і бюджет). Другий план — другий ledger.

## Baseline

| Поле | Що це |
|---|---|
| `Id` | PK |
| `Date` | дата документа |
| `InOut` | знак плеча: `+1` дебет, `-1` кредит |
| `Acc` | рахунок плеча — FK на план із `accplan` |
| `CorrAcc` | кореспондуючий рахунок — `Acc` протилежного плеча |
| `Sum` | сума плеча |

Імена baseline не авторські: `post` пише ці колонки зі своїх ключів. У `fields` не пишуться.

## `fields` — походження, аналітика, міри

**Походження оголошує автор, як у журналі** ([journal.md](journal.md)) — платформа знаходить колонки **за типом**:

| Тип | Що це |
|---|---|
| `document` | документ-джерело; ціль — де живуть документи застосунку (`/document`), її знає лише автор. **Обов'язкова**: на ній тримаються розпроведення й `ShowTrans` |
| `documentType` | дискримінатор сховища, якщо документи в кількох таблицях |
| `operation` | операція документа; документ без операцій пише `null` |
| `row` | Id рядка-джерела для плеча, що читає рядок (див. «Згортка плеча») |

**Аналітика й міри — звичайні колонки**, nullable, розріджені: кожне плече заповнює свої. Складу аналітики по рахунку ніде не оголошено — субконто немає; незаповнений розріз звіт показує рядком «Не вказано».

## Запис — `post` документа

```jsonc
// document/waybillin/metadata.json
"post": [
  { "ledger": "/ledger/national",
    "each": { "details": "Rows", "kinds": ["Stock"] },
    "sum":  "Sum",
    "dt": { "const":    { "Acc": "281" },
            "row":      { "Item": "Item", "Qty": "Qty" },
            "document": { "Store": "StoreTo" } },
    "ct": { "const":    { "Acc": "631" },
            "document": { "Agent": "Agent" } } }
]
```

| Ключ | Required | Призначення |
|---|---|---|
| `ledger` | ✅ | Endpoint-шлях ledger-а |
| `sum` | ✅ | Поле суми: рядка, якщо є `each`, шапки — якщо ні. Одна на обидва плеча |
| `dt`, `ct` | ✅ | Плечі: у кожному блоки `const` / `document` / `row` |
| `each` | ⚪ | Як у журналі ([metadata.md](metadata.md) → `post` → «`each`») |

Дві осі — два рівні ключів: **плече** зовні, **джерело значення** всередині. Блок — мапа `{ поле ledger: значення }`:
- `const` — літерал; `document` — поле шапки; `row` — поле рядка з `each`. Літерал від імені поля відрізняє **ключ блоку**, не вигляд рядка;
- **у кожного плеча рівно один `Acc`**, в одному з блоків;
- ключі блоків — `Acc` або колонки автора, крім походження;
- значення — голе ім'я поля, шляху крізь `Ref` немає: рахунок, що живе на довіднику, приходить у документ через `inherit` ([rules.md](rules.md));
- **auto-mapping немає**: ім'я не знає плеча й заповнило б обидва рядки. У ledger пишеться все, за іменем не виводиться нічого;
- `CorrAcc`, `InOut`, `Date`, походження — заповнює платформа.

`dir`, `storno`, верхньорівневі `document` / `row` у ledger-записі не пишуться — помилка при завантаженні. Процедура (`sql` + `journals`) у ledger сьогодні не пише: `journals` приймає лише журнали.

**Перевіряється при завантаженні:**
- `ledger` вказує на ledger, `journal` — на журнал;
- літерал `const.Acc` — код із `seed.json` плану; рахунок користувача літералом не пишеться;
- `const` — значення підходить колонці; `document` / `row` — поле існує, домен і `target` збігаються з колонкою ledger-а;
- одне поле у двох блоках плеча, плече без `Acc`, `row` без `each`, ключ-походження чи baseline — помилка.

**Баланс структурний:** обидва плеча беруть суму з тих самих рядків — перевірки «дебет = кредит» немає й не потрібно. Складна проводка (один Дт, кілька Кт різними сумами) — кілька записів у `post`.

## Згортка плеча

**Плече, що нічого не бере з рядка (немає блоку `row`), згортається до шапки.**

Накладна на два товари з прикладу вище:

| InOut | Acc | CorrAcc | Sum | Row | Item | Qty | Store | Agent |
|---|---|---|---|---|---|---|---|---|
| +1 | 281 | 631 | 242 | 1002 | Перший товар | 11 | Основний | |
| +1 | 281 | 631 | 22 | 1004 | Другий товар | 2 | Основний | |
| −1 | 631 | 281 | 264 | | | | | Перший |

- плече з `row` — рядок на рядок документа, `Row` = рядок-джерело;
- плече без `row` — `Row = null`, групується за всіма колонками, крім `Sum`; `Sum` сумується;
- `CorrAcc` — у ключі групування: різні дебетові рахунки по рядках дають кредит по рядку на кореспонденцію;
- ключа немає — згортка випливає з блоків плеча.

**Розпроведення** — видалення за колонкою `document` (+ `documentType`), як у журналу.

## Екрани

- **index** — стрічка **плечей**, як index журналу: колонки з baseline і `fields`, фільтр періоду за `Date`, смуга `Edit`. `Acc` / `CorrAcc` показуються кодом: `presentation` плану — код ([accplan.md](accplan.md)). Журнал «Дт | Кт | Сума» — це `InOut = 1`, прочитаний як `Acc | CorrAcc`; окремою формою index його немає.
- **`ShowTrans`** документа — вкладка на кожен ledger, у який він проводить.

**Локалізація**, яку дає застосунок ([localization.md](localization.md)): `@[InOut]`, `@[Acc]`, `@[CorrAcc]` і підписи полів автора (`@[Document]`, `@[Operation]`, `@[Row]`, …).

**Меню:** `/ledger/<name>` — самостійний вхід ([menu.md](menu.md)).

## 🚧 Не реалізовано

- **сальдо** — рівень згортки (весь рахунок чи за аналітикою) не оголошується;
- **одинарна проводка** на забалансовому рахунку (`OffBalance`) — невиразна: у записі завжди обидва плеча;
- **поле-рахунок у документі** (`document: { "Acc": "SupplierAcc" }`) — формат приймає, але домен `Account` у платформі без вибору ([accplan.md](accplan.md) → «Посилання на рахунок»);
- **звіти з вибором** над ledger-ом (аналіз і картка рахунку, розгорнуте сальдо за аналітикою). ОСВ і шахматка є — `trialBalance`, `chessboard` ([report.md](report.md)).
