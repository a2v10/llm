# `rules` і `properties` — правила полів і властивості моделі

Два блоки-сусіди `fields` у своїй області:

- `rules` — правила, що пов'язують поле з іншими полями **того самого запису**: чи обов'язкове, чи видиме, звідки приїжджає по посиланню, підсумок колонки;
- `properties` — **чому дорівнює значення**: властивість моделі з get і, можливо, set.

Що приходить ззовні запису — не тут: початкові значення — `initialValues`, канали вводу посилання — `lookup`, структура — `fields`.

## Де живе

Область задає **позиція**, як в `initialValues` і `lookup`:

| Де блок | Про що |
|---|---|
| поруч із `fields` шапки | поля шапки |
| `details.<Collection>` | поля рядків колекції |
| `details.<Collection>.kinds.<Kind>` | поля рядків **цього виду** ([metadata.md](metadata.md) → «`kinds` — види рядків») |

Документ із власною таблицею пише `rules` поруч зі своїми `fields` — шар один. Над спільною таблицею шарів три:

1. власник таблиці — корінь `document/metadata.json`;
2. документ над `storage` — `document/<name>/metadata.json`: пише `rules` і `details.<Collection>.rules` (і `properties`) без shape-ключів;
3. операція — `<op>.operation.json` (version >= 8671): `rules`, `details.<Collection>.rules`, `details.<Collection>.kinds.<Kind>.rules` діють, поки документ несе цю операцію. Тест пише платформа; обмеження ті самі, що в `when` (нижче). `properties` в операції — помилка завантаження.

### Як зливаються шари

| Вид | Злиття |
|---|---|
| `required`, `skipBoundary` | об'єднання |
| `visible`, `inherit` | по ключу поля, верхній перекриває |
| `when` | склеювання, корінь першим (version >= 8671) |
| `properties` | по ключу, верхній перекриває |

Той самий закон — на осі «колекція → вид рядка»: вид, що не написав нічого, отримує правила колекції; що написав — кладе своє поверх.

**Ослаблення не пишеться.** Зняти `required` кореня (чи колекції) документ (чи вид) не може, прибрати властивість кореня — теж. Вимога чи властивість, вірна не для всіх, оголошується нижче — у тих документах чи видах, яким потрібна.

## Одиниця оголошення — правило, а не поле

Ключ блоку — **вид правила**; імена полів — усередині:

```json
"rules": {
  "required": ["StoreTo", "Agent"],
  "inherit":  { "Unit": { "ref": "Item", "field": "Unit" } }
}
```

Не `{ "StoreTo": { "required": true } }`.

## Види правил

| Вид | Форма | Що робить | Стан |
|---|---|---|---|
| `required` | `string[]` — імена полів | поле має бути заповнене | працює |
| `total` | `string[]` — імена полів **колекції** | дає `this.<Collection>.<Field>` — суму колонки | працює; рядка підсумків форма не малює |
| `visible` | `{ <Field>: вираз }` | поле видно, поки вираз істинний | 🟡 не діє: поле видно завжди |
| `inherit` | `{ <Field>: { ref, field } }` | при виборі `ref` копіює поле цілі | працює |
| `skipBoundary` | `string[]` — `Ref`-поля на довідник-вимір | поле не підпадає під межу юзера ([permissions.md](permissions.md) → «Межа») | 🚧 |
| `when` | `[ { test, <види правил> } ]` | правила діють, поки `test` істинний | лише `required` (version >= 8671) |

### `required`

- Список імен, більше нічого. Коли вимога спрацьовує, каже kind: каталог — збереження, документ — проведення ([metadata.md](metadata.md) → «`NOT NULL` і `required`»).
- На полі домену з нулем (`Qty`, `Amount`, `Boolean`, …) незаповнене — нуль, тому `required` там означає «не 0» / «позначено». `NOT NULL` дає домен, не `required`.
- `$`-імена не приймає: обчислюване значення є завжди.
- Повідомлення не оголошується: `@[Error.Required]` + `title` поля.

### `total`

- Лише на колекції (чи виді); на шапці — помилка завантаження.
- Кожне ім'я дає член **масиву** рядків: `"total": ["Sum"]` на `Rows` → `this.Rows.Sum`. Колекція з `kinds` — член кожного виду: `this.StockRows.Sum`, `this.ServiceRows.Sum`.
- Без `total` такого члена немає — тоді сума пишеться прямо: `this.Rows.$sum(r => r.Sum)`.
- Рахує клієнт по завантажених рядках, не SQL.

### `when` — умова над правилами

Умова — область над правилами, не параметр правила:

```json
"rules": {
  "required": ["StoreTo", "Agent"],
  "when": [
    { "test": "this.PaymentType === 'credit'", "required": ["DueDate", "CreditDays"] }
  ]
}
```

- `test` — JS-вираз над записом своєї області («Вирази» нижче); у правилах рядка — над рядком, поле шапки — `this.$root.<Model>.<Field>`.
- Усередині — ті самі види в тих самих формах. Глибина рівно 1: `when` у `when` немає.
- Правила зі `when` **додаються** до безумовних. Поле, обов'язкове безумовно, умова не послаблює.
- Під умовою працює лише `required` (version >= 8671). `inherit` і `total` у `when` — помилка завантаження: пиши їх безумовно. `visible` у `when` — 🟡, як і безумовний.
- Умови по виду рядка немає (`this.Kind` не існує) — правило виду пишеться в `kinds.<Kind>.rules`.

### `visible`

🟡 Оголошується й зливається, але **не діє**: генератора немає, поле видно завжди. Значення — вираз. Статичного `visible: false` немає: приховати безумовно = прибрати поле зі складу форми.

### `inherit` — значення по посиланню

```json
"inherit": { "Unit": { "ref": "Item", "field": "Unit" } }
```

- **Знімок у момент вибору.** Зміна `ref` завжди перезаписує отримувач: обрав товар — отримав його реквізити. Далі значення належить запису й від джерела від'єднане. Режиму «лише якщо порожньо» немає.
- `ref` — `Ref`-поле **тієї самої** області, що й отримувач: поле рядка — серед полів рядка, поле шапки — серед полів шапки. `field` — поле endpoint-а з `target` цього `ref`; тип сумісний.
- `field` обов'язковий, навіть коли ім'я збігається з отримувачем.
- **Один хоп.** `VatRate ← Item.Group.VatRate` не виражається: заведи в `Item` поле `VatRate` з власним `inherit` від `Group`.
- Позначати поле-джерело на цілі не треба — платформа сама доносить його до клієнта.
- Одне поле — одне джерело значення: `inherit` і властивість на одному полі — помилка.
- `inherit` не скасовує `required`: поки `ref` не обрано, отримувач порожній.

## Правила по видах рядків

Колекція з `kinds` приїжджає окремою колекцією на кожен вид зі складеним іменем: `Rows` з видами `Stock`, `Service` → `this.StockRows`, `this.ServiceRows` ([metadata.md](metadata.md) → «`kinds` — види рядків»).

```json
"kinds": {
  "Stock":   { "properties": { "Sum": { "get": "this.Qty * this.Price" } },
               "rules": { "required": ["Item", "Qty", "Price"] } },
  "Service": { "rules": { "required": ["Description", "Sum"] } }
}
```

- Правило колекції діє в кожному виді; правило виду — лише у своєму.
- Вид — свій тип, тож одне поле може бути обчислюваним в одному виді й вводитися в іншому (`Sum` вище).
- Колонки виду — ті самі, що в колекції; власних полів вид не має.

## Вирази

JS, повна форма з `this.`: `"this.Qty * this.Price"`, не `"Qty * Price"`.

- Імена: `fields` ∪ baseline ∪ `$`-імена `properties` своєї області. У виді — колонки колекції плюс `$`-імена колекції й свої.
- Поле шапки з рядка — `this.$root.<Model>.<Field>` (`this.$root.Document.PaymentType`).
- Колекція — так, як вона приїхала: з `kinds` — імена видів (`this.StockRows`), `this.Rows` там немає. Підсумок по всіх видах — перерахуванням: `this.StockRows.Sum + this.ServiceRows.Sum`.
- 🚧 **Вирази не перевіряються** ні завантаженням, ні `a2 meta validate`: опечатка в `this.X` проявиться лише в браузері. Звіряй імена з `fields` самостійно.
- Проміжне ім'я (`$`-властивість) — коли значення потрібне двічі або показується у формі.

## `properties` — властивості моделі (version >= 8668)

Ключ — ім'я властивості, значення — `{ get }` або `{ get, set }`, як `computed` у Vue:

```json
"fields": {
  "Qty":   { "type": "qty" },
  "Price": { "type": "price" },
  "Sum":   { "type": "amount" }
},
"properties": {
  "Sum":   { "get": "this.Qty * this.Price", "set": "this.Qty = value / this.Price" },
  "$Base": { "type": "amount", "get": "this.Qty * this.Price" }
}
```

| Ключ | Що це | `type` | Збереження |
|---|---|---|---|
| поле з `fields` / baseline | властивість над колонкою; у колонку їде те, що повернув get | заборонений — тип у `fields` | їде |
| `$Ім'я` | власне ім'я без колонки | обов'язковий; лише скалярний домен (`amount`, `qty`, `percent`, `date`, `string`, `boolean`), не посилання | не їде ніколи |

- Форма значення — лише об'єкт; рядка-скорочення немає.
- `get` — вираз; `set` — JS-оператор над `value` (тим, що ввів користувач), пише в поля свого запису.
- Без set форма поле показує й не дає вводити; із set — звичайний контрол домену.
- `$`-ім'я форма називає в `fields` вузла, як поле ([forms.md](forms.md)), — лише у формі `edit`; список і пікер властивостей не мають.
- Шарування — по ключу, на обох осях. Документ над `storage` оголошує свої властивості вільно — інші документи над тією самою таблицею їх не бачать.
- Ключів `computed` / `derived` немає — це `properties`.

### Як поле отримує значення

| Як | Що | Коли |
|---|---|---|
| нуль домену | тип поля (`0` / `false`, решта `NULL`) | створення |
| при створенні запису | `initialValues` | Load |
| знімок при виборі посилання | `inherit` | зміна `Ref` |
| завжди дорівнює виразу | `properties` (get) | постійно |
| обчислює БД | `sqlAs` у `fields` ([metadata.md](metadata.md) → ключі поля) | читання |

Одне поле — одне джерело значення: `inherit` і властивість разом — помилка. Властивість і `sqlAs` на одному полі можливі, узгодженість виразів — на авторі.

### Лінза — властивість із set

get показує значення, set розкладає введене назад у первинні поля. Де стоїть:

| Смисл показаного | Де | Приклад |
|---|---|---|
| фіксований | над колонкою, зберігається | `Sum = Qty × Price`; ввів суму — set рахує `Qty` або `Price` |
| залежить від режиму | лише `$`-ім'я | ціна з ПДВ чи без за `VatIncluded` — над `Price` зламала б смисл колонки |

- **Трикутник `Qty × Price = Sum`:** що рухати при вводі суми, вирішує автор — `"this.Qty = value / this.Price"` чи `"this.Price = value / this.Qty"`.
- set має повертати введене: ввів 100 — get показує 100 (у межах округлення).
- Програмний запис іде повз set: народження, `inherit`, завантаження пишуть первинні поля напряму.
- 🟡 ПДВ — не авторська лінза, а правило `vat`; у нормі його ще немає.

## Чого в `rules` немає

- **Перевірок значення** (`min` / `max` / `regex` / `unique` / довжина) — вони виводяться з `fields`: `length`, `unique`, домен ([metadata.md](metadata.md) → «Що НЕ пишеться у field»). 🟡 Уточнення домену конкретного поля (`min` / `max` / `pattern` поруч із `length`) — форма не описана.
- **`readonly`** — runtime-прапор запиту ([forms.md](forms.md) → «`readonly`»).
- **`validators`, `events`, `requiredMessage`** — генератор обирає сам.
- **Умов по виду рядка** — позиція `kinds.<Kind>.rules`.
- **`$`-імен у серверних позиціях**: `post`, `initialValues`, `inherit` (як отримувач), `lookup`, `presentation`, `displayAs`, виміри й ресурси журналу — значення не доїжджає до сервера.

## Валідація

Помилка завантаження:

- ім'я поля не резолвиться у своїй області (`fields` / baseline / `$`-імена) — у `required`, `total`, `when.required`, `inherit`, `properties`;
- `total` на шапці;
- `when` без `test`; `inherit` чи `total` у `when` (version >= 8671);
- `inherit`: `ref` не `Ref`-поле; `field` немає в цілі;
- `properties` (version >= 8668): немає `get`; ключ без `$` не є полем або має `type`; `$`-ключ без `type` чи з доменом-посиланням; властивість на полі з `inherit`; `properties` у файлі операції;
- ключ у `kinds`, якого немає серед видів колекції (з переліком `Available: …`).

Незнайомий ключ (невідомий вид правила, вкладений `when`) завантажувач **мовчки викидає**; відхиляє його JSON Schema — редактор і стадія `schema` у `a2 meta validate` (version >= 8670). Запускай `validate`.
