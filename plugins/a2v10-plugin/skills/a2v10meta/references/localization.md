# Localization Conventions

Файлы локализации хранятся в папке `_localization` и читаются платформой для текущей локали пользователя.

## Именование файлов

Формат: `<name>.<locale>.txt`

| Пример               | Локаль      |
|----------------------|-------------|
| `_default.uk.txt`    | Украинский  |
| `_default.en.txt`    | Английский  |

Платформа читает все `*.<locale>.txt` папки по алфавиту; ключ, повторённый в двух файлах, берёт значение из последнего. В приложении файл один — см. «Правило: один файл для всех ключей».

## Формат файла

```
; Комментарий
@Key=Значение
```

- Строки с `;` — комментарии.
- Каждая запись: `@Key=Локализованное значение`.
- Ключи — без пробелов, регистрозависимые.

## Соглашения по ключам

Сущности именуются в единственном и множественном числе:

```
@Sample=Зразок
@Samples=Зразки
```

Поля именуются по имени колонки/свойства:

```
@Name=Назва
@Memo=Примітка
```

## Использование в шаблонах

Ссылка на локализованную строку в шаблоне — через `@[Key]`, в обратных кавычках: перевод подставляется в текст скрипта, и апостроф («Обов'язкове») закрыл бы строку в одинарных:

```typescript
validators: {
    'Sample.Name': `@[Error.Required]`
}
```

## Правило: один файл для всех ключей

Все ключи локализации — как общие UI-ключи, так и ключи новых сущностей — добавляются в единственный файл `_default.uk.txt`.

**Entity-specific файлы локализации не создаются.**

При генерации нового справочника — в конец `_default.uk.txt` дописывается секция с ключами этой сущности. Например, для сущности `Agent`:

```
; Agent
@Agent=Контрагент
@Agents=Контрагенти
@Agent.Browse=Вибір контрагента
@Agent.All=Усі контрагенти
@Phone=Телефон
@Email=Email
@Address=Адреса
```

## Ключі, яких потребує форма списку

Генерована форма списку й лукап посилаються на ключі, яких у `fields` не видно, — тому їх дописують **разом із формою**, а не після першого запуску, коли `@Agent.All` вилізе сирим на екран.

| Ключ | Звідки береться | Скільки |
|---|---|---|
| `@<Field>` | заголовок колонки; для натурального ключа — `@Code` | по одному на поле |
| `@<Model>` | підпис фасета за посилальним полем — **ім'я моделі цілі**, не поля | по одному на ціль |
| `@<Model>.All` | плейсхолдер «усі» в тому ж фасеті | по одному на ціль |
| `@<Model>.Browse` | заголовок діалогу вибору | по одному на ціль |
| `@Operation.<код>` | назва операції: деплой пише її в `doc.Operations.Name`, вона ж — заголовок картки; код — ім'я документа (`waybillin`) або `<документ>.<op>` (`receipt.gratis`), а `@Operation.<документ>` — заголовок картки документа з `operations` ([metadata.md](metadata.md) → «Коди операцій») | по одному на код; ще один на документ з `operations` |

**`@<Model>` фасета — це модель цілі посилання, а не ім'я поля.** Три поля, що дивляться на один довідник, дають один ключ, а не три; поле `HeadCounterparty` із ціллю `/catalog/counterparty` підписується `@Counterparty`.

## Ключі платформи

Застосунок пише лише ключі, складені з **його** імен (таблиця вище). Решту дає платформа — `default.*.txt` і `metadata.*.txt` пакета `A2v10.Metadata`, сім мов (version >= 8670):
- команди, підтвердження, валідація (`@Error.Required`, `@Error.Duplicate`) і повідомлення про помилки (`@Error.Owner`, `@Error.Delete.Used`, `@Error.Document.*`);
- фасети й панелі: `@Filters`, `@Period`, `@Tags`, `@Filter.Tag.All`, `@Folder`, `@Folders`, `@Ungrouped`;
- спільна таблиця операцій: `@Operation`, `@Operation.All`, `@Operation.Browse`;
- закриті набори й колонки платформи: `@StateRole.*`, `@AccountType.*`, `@NormalBalance.*`, `@Parent`, `@SplitBy`, `@InOut`, `@Acc`, `@CorrAcc`;
- звіти: `@Report.*`, `@Grouping`, `@Data`, `@Total`, `@TurnOver.*`, `@TrialBalance.*`, `@Account`, `@Debit`, `@Credit`, `@Chessboard.*`.

У `_default.uk.txt` застосунку їх **не дописувати**. Інший переклад — той самий ключ у `_localization` застосунку: він читається після платформних і перекриває їх.
