# MCP — застосунок для моделі користувача (version >= 8673)

Застосунок відкривається моделі користувача (Claude) за адресою `/mcp`: модель шукає в довідниках і документах, створює й проводить документи, питає звіти — **як сам користувач**, під його входом і з його правами. Тули дає платформа, однакові для всіх застосунків; застосунок пише лише список сутностей і текст про себе.

## Що де

| Де | Що | Хто пише |
|---|---|---|
| `WebApp/Startup.cs` — `services.UseMcp(...)`; `WebApp.csproj` — пакет `A2v10.Mcp` | транспорт `/mcp` і вхід (OAuth) | є в `scaffold/`, не чіпати |
| `WebApp/appsettings.json` → `Mcp:PublicUrl` | адреса, яку людина вводить у коннектор, без `/mcp` | `scaffold/`: `http://localhost:5000` |
| `WebApp/appsettings.json` → `Application:PublicUrl` | адреса застосунку: з неї посилання на звіт у відповіді моделі. Немає — `report_query` відмовляє | `scaffold/`: `http://localhost:5000` |
| `MainApp/mcp.json` | які сутності бачить модель. Файла немає — відмова на будь-якому запиті моделі | `scaffold/` — порожній; список — ти |
| `MainApp/mcp-instructions.txt` | що це за застосунок | ти |
| ключ `mcp` у `metadata.json` | що виводиться хибно | ти, лише де треба |

Обидві адреси — та, на якій хост справді слухає. Хост запущено деінде — змінюються обидві.

## `mcp.json`

```json
{
  "$schema": "@schemas/mcp-json-schema.json#",
  "endpoints": [
    "/catalog/agent",
    "/catalog/item",
    "/catalog/store",
    "/catalog/unit",
    "/document/waybillin",
    "/document/waybillout",
    "/report/stockturnover"
  ]
}
```

- **Що вносити: кожен каталог, документ і звіт, який відкриває `menu.json`.** Журнал, ledger, план рахунків, enum, autonum — ні: інший kind — відмова.
- **Каталог, на який посилається поле документа зі списку, — теж у списку.** Інакше модель бачить поле як `unavailable` і не заповнить його.
- **Поле `account` моделі завжди `unavailable`**: план рахунків у список не входить. Рахунок, який вводить людина в рядку, через MCP не ввести.
- **Ім'я сутності для моделі — тека** (`agent`). Дві однакові теки під різними kind-ами (`catalog/payment`, `document/payment`) — відмова.
- Хто бачить: ролі — `roles` кореня `model.json` теки; метаендпоінт без `model.json` бачить кожен, хто увійшов.
- 🚧 Endpoint у теці-аліасі (`sale/invoice`, [kinds.md](kinds.md) → aliases) не вносити: виклик над ним падає.

**`a2 meta validate` цього файла не перевіряє.** Будь-яка відмова вище — при першому підключенні моделі, і падає весь список тулів, з іменем шляху. Звір список з текою сам.

## `mcp-instructions.txt`

Звичайний текст у корені `MainApp`, до 2 КБ (Claude Code обрізає довше). До першого виклику модель має лише його й імена тулів.

```text
Wholesale food trade: stock in stores, settlements with suppliers and customers, double-entry books.
Records are in Ukrainian.
To learn what it holds, call domain_info.
Several companies keep their books here: every document belongs to one, ask the user which.
A return is created on basis of the document it returns.
```

- **Рядок `To learn what it holds, call domain_info.` — обов'язковий.** Без нього модель починає навмання.
- Що писати: що за застосунок і для кого, мова записів, особливості предметної області, які не видно з полів.
- Що не писати: перелік сутностей і полів (дає `domain_info` і `*_info`, з урахуванням ролей), імена тулів, правила, що вірні для будь-якого застосунку.
- Мова — англійська, як описи тулів.

## Ключ `mcp` у `metadata.json`

Лише на endpoint-і з `mcp.json` і лише те, що виводиться хибно:
- `description` — що це, коли ім'я теки не каже (`domain_info` показує поруч з іменем);
- `measures` у звіту — що означає міра, коли ім'я й тип не кажуть: `Sum` — собівартість чи виручка.

```json
"mcp": { "measures": { "Sum": "Собівартість" } }
```

Назви сутностей модель бере з локалізації, тієї самої, що й екран: заголовок документа — `@[Operation.<документ>]`, каталогу — `@[<Model>]`, звіту — `@[Reports.<звіт>]` (version >= 8674) ([localization.md](localization.md)). Окремої назви для моделі немає; ключ без перекладу модель отримує як є.

## Що модель робить через MCP і чого ні

- **Може:** шукати й читати записи, створювати й змінювати записи каталогів і чернетки документів, документ на підставі іншого й з операцією, проводити й розпроводити, питати будь-який звіт зі списку.
- **Рахує сама.** Вирази `properties` і `inherit` виконує лише браузер: ціну з картки товару, суму рядка модель заповнює й надсилає сама. Значення, що виводяться, вона бачить в описі поля.
- **Компанію називає сама.** Перемикача компанії в `/mcp` немає; документ без компанії не проводиться. Кілька компаній — скажи про це в `mcp-instructions.txt`.
- Посилання на створений документ у відповіді немає; на звіт — є.

## Підключення

Сервер запускає користувач. Адреса коннектора — `Mcp:PublicUrl` + `/mcp`, за умовчанням `http://localhost:5000/mcp`.

- **Claude Code** (вкладка Code у Claude Desktop) — головний клієнт, ходить локально:
  ```bash
  claude mcp add --transport http <AppName> http://localhost:5000/mcp
  ```
  Вхід і згода відкриваються в браузері — той самий логін, що й у застосунку.
- **claude.ai і чат Desktop** ходять із хмари: потрібна публічна HTTPS-адреса (тунель), і обидва `PublicUrl` — вона. `mcp-instructions.txt` claude.ai не читає.
