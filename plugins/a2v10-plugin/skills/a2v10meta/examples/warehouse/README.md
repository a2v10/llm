# warehouse — приклад застосунку

Складський облік: чотири довідники, набір ставок ПДВ, чотири документи над спільною
таблицею (прихід / видаток / повернення / переміщення — кожен з однією неявною операцією), журнал
запасів, оборотний звіт, реєстр нумерацій. Документа зі списком `operations` тут немає.

**Це готовий застосунок, а не заготовка.** У теці endpoint-а рівно один файл — той,
що його оголошує. XAML, SQL і TypeScript тут немає не тому, що приклад скорочено:
їх немає в жодному metaendpoint-і, поки якийсь артефакт не ejected навмисно
([materialize.md](../../references/materialize.md)).

Виняток — `waybillout/print/waybill.json`: друкований бланк файлом існує **завжди**,
бо це чужий формат (Workbook), а не матеріалізований артефакт. Скіл тримає в ньому
один розділ — `Model` ([print.md](../../references/print.md)).

Читати варто **між файлами** — усе, що видно всередині одного, сказане в
[references/](../../references/) при відповідному правилі. Між файлами лежить:
`target` → тека довідника, `storage` → корінь `document/metadata.json`, `post.journal` →
виміри й міри журналу, `autonum` → ключ у мапі `autonums`, `surface` звіту → той самий
журнал, `printForms.path` → файл бланка, `menu.json` → кожен endpoint, який має
власний вхід. Порядок написання —
той самий, що в [onboarding.md](../../references/onboarding.md): enum → довідники →
журнал → autonum → корінь спільної таблиці → документи над нею → звіт.

`enum/vatrate` і `autonum` у `menu.json` не згадані — свого екрана в них немає.

`Tests/scenarios/` — сценарії ([tests.md](../../references/tests.md)). У застосунку `Tests/`
лежить поруч із `MainApp/`; тут — поруч із його файлами. Між файлами в них: `at` → тека
endpoint-а, `Rows` → ключ `details` кореня (видів у ньому немає, тому колекція одна й
зветься так само), `{ "ref": … }` → запис із `records`. У `stock-move` залишків немає: `expect`
за звітом ще не вирішений, і `requirement` це каже. Прикладу їх ніхто не проганяє —
поля звірені з файлами вручну.

Нормативний опис — `references/`. Розійшлися — правий він.
